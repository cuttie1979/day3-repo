# S2 · Az `opencode-configuration` skill

**A nap központi eszköze.** Ez a skill konfigurálja az MCP-ket, az agenteket és a permission-öket — és a
nap üzenete szerint **az eszközt eszközzel** állítjuk be, nem kézzel írjuk a JSON-t.

Három dolgot tettem hozzá a szöveghez, mert nélküle a skill tippelni fog:

| | |
|---|---|
| **a konfig helye** | globális: `~/.config/opencode/`; projekt: `<project>/.opencode/` — ki kell mondani |
| **a rollback** | git alatt egy `git checkout -- .` a visszaállás; **egy** `rollback.sh` elég, nem módosításonként egy |
| **a commit** | minden **sikeres** módosítás után commitoljon, hogy legyen mihez visszaállni |

**Amit utána ellenőrzünk:** létezik-e a `SKILL.md`, és a skill leírja-e a három dolgot (hely, rollback,
commit).

```
Please create an OpenCode skill named opencode-configuration, whose job is to change the OpenCode configuration.

Use these pages as the source of truth: https://opencode.ai/v2/docs/agents/ , https://opencode.ai/v2/docs/skills/ , https://opencode.ai/v2/docs/mcp-servers/ , https://opencode.ai/v2/docs/permissions/

Before every change, check the parameters and their allowed values against that documentation. Where JSON is used, validate it against the schema.

The configuration lives in two places: the global directory ~/.config/opencode/ and a project's .opencode/ directory. Unless the user asks for global, always work in the project-specific configuration.

That configuration directory is a git repository. Make one rollback script (rollback.sh) that restores the last committed good state, and commit after every successful change — do not create a separate script per change. At the end of every change, show the user how to run rollback.sh.

For agents, use the markdown format.

This skill is global: install it under ~/.config/opencode/skills/opencode-configuration/.
```
